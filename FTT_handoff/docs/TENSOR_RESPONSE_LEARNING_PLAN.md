# Research Plan — Tensorized Response Learning for Branch-and-Price Search

**Thesis.** Low-rank / spectral / tensor structure should be used not to compress *networks* but to
understand the **solver's response field** — the primal, dual, value, bound, and branch-action responses
that branch-and-price generates as it runs. The question shifts from *"can a neural net learn a branch
policy?"* to *"what is the low-rank tensor structure of the primal–dual response field generated by
branch-and-price, and how does it guide exact search?"*

This plan is the deepened version of what we already built and measured (Stages A–C + the
gradient-weighted screening theory). It is grounded in the train-scheduling B&B
(`spectral_ttbl/ttbl_bnb.py`) as the data-generating process.

---

## 1. The central object: the response tensor

The solver emits, at every node, a structured response. Collect it as a multi-way tensor
```
   R[ n, a, p, r, m ]
     n = branch node / state / instance
     a = candidate branch action (meet-pass conflict, departure split, …)
     p = trajectory / column (train space-time path)
     r = resource-time cell (section,t)/(station,t)        <-- the H rows
     m = response metric  ∈ { ΔLB, ΔUB, Δgap, Δviolation, Δdual λ, Δprimal x, Δpricing }
```
This is the tensor generalization of the paper's `H` (resource×trajectory) and `B`
(trajectory×action): `G = HB` is one 2-way slice of `R`. CP / Tucker / tensor-train factor it:
```
   CP:     R[n,a,p,r,m] ≈ Σ_ℓ α_ℓ uℓ(n) vℓ(a) wℓ(p) xℓ(r) yℓ(m)
   Tucker: R ≈ 𝒢 ×₁U^node ×₂U^action ×₃U^traj ×₄U^resource ×₅U^metric
```
Each latent mode ℓ is interpretable: *capacity-bottleneck mode, terminal-congestion mode, meet-pass
conflict mode, departure-shift mode, dual-scarcity mode, UB-repair mode, LB-tightening mode.*

---

## 2. The bridge from what we already have (matrix) to the tensor

Our gradient-weighted screening theorem (run on train scheduling, `screening_theory.py`) already is a
**rank-decomposed regression**:
```
   ΔS(a) ≈ ∇Sᵀ Δx(a) ,   Δx(a) ≈ Σ_i σ_i u_i (v_iᵀ b_a)
   ⇒  ΔS(a) ≈ Σ_i σ_i (u_iᵀ∇S)(v_iᵀ b_a)
```
Three factors per mode — already measured on our data:

| factor | meaning | status in our code |
|---|---|---|
| `σ_i` | response variance strength | computed (`screening_theory.py` SVD) |
| `u_iᵀ∇S` | value/gradient sensitivity | computed (the gradient-weighted tail; the cliff at low-energy dirs) |
| `v_iᵀ b_a` | action alignment | **the missing factor the tensor model learns across instances** |

So the correct branch score is **not** the unsupervised norm `‖ΣVᵀb_a‖` (which fails — Containment@1
0.17) but the gradient-weighted sum `Σ_i σ_i(u_iᵀ∇S)(v_iᵀb_a)` (the learned score wins — 0.37/0.92).
The tensor framework is: **stop fitting one `(σ, u, v)` per node; fit shared latent factors across
nodes/instances** → generalization + interpretability + sample efficiency.

## 3. Literature positioning (where this is genuinely new)

| stream | representative | what they do | what they miss |
|---|---|---|---|
| Low-rank MDP / Bellman rank | Jiang+ 2017; linear/low-rank MDP | low-dim Bellman/transition structure | object is `P(s'|s,a)`, not solver response |
| Tensor value-function RL | Rozada–Paternain–Marques 2022/24; multi-task Q-tensor | low-rank V/Q approximation | DP/RL, not exact-optimization search |
| Tensor-train optimal control | Gorodetsky–Karaman–Marzouk; TT-DP | compress high-dim value functions | not branching/pricing/action response |
| Tensor state-action rep | Ni+ 2021 (low-Tucker kernel) | learn state/action reps for MDPs | not B&P primal–dual response |
| Learn-to-branch GNN | Gasse+ 2019; Gupta+ 2022; Achterberg reliability | imitate strong branching on MILP graph | black-box graph policy, **no explicit response tensor** |
| **This work** | — | tensorize the primal–dual / action–trajectory–resource response of B&P | connects spectrum + gradient + dual value + **exact certification** |

The deep point nobody combines: **the solver is a data-generating process**, and its response field has
multilinear (tensor) structure dictated by resource constraints, trajectory incidence, dual prices, and
bound updates — not arbitrary.

## 4. The data-generating process (we already have it)

`ttbl_bnb.py` + `learn_branch.py` already emit, per node: candidate actions `a`, child schedules
(`Δprimal`), child bounds (`ΔLB/ΔUB`), conflict structure, and the resource-time footprints. We log
`(footprint, structural features, exact Δ)` (Stage C) and trajectory/action pools (Stage B). To build
`R` we add the missing metric slices (dual λ from the LR/longest-path, pricing/violation) and stamp
node/instance indices. **No new solver needed — just richer logging of the one we built.**

## 5. Research stages (build directly on Stages A–C)

- **T1 — Assemble the response tensor.** Extend the B&B loggers to emit `R[n,a,r,m]` (start with
  m ∈ {ΔLB, ΔUB, Δprimal-shift, dual-pressure}); store as sparse COO + index maps. Multiple instances
  (seeds, train counts) → the `n` mode carries cross-instance variation.
- **T2 — Decompose & interpret.** CP and Tucker on `R`; report per-mode energy and **name the modes**
  (meet-pass / departure-shift / dual-scarcity / LB-tightening). Deliverable analogous to Fig 2 but
  multi-way; validate modes against known conflict structure.
- **T3 — Gradient-weighted tensor-regression screen.** Replace the per-node SVD score with a
  **shared-factor** model `ΔŜ(n,a)=Σ_ℓ αℓ uℓ(n) vℓ(a)` fit across training instances; the key new test
  is **transfer**: train on instances 1..K, screen on unseen instances. Metrics (same as Stage C):
  Containment@K, tie-cluster `K'`, RankGap — but now *out-of-instance*. Hypothesis: shared low-rank
  factors beat per-node SVD and the learned-per-node GB model on transfer.
- **T4 — Scale to where it pays off.** Move to N-track / route-choice (Meng-Zhou) instances where the
  candidate set is large and child evaluation is expensive (single-track had mean |A|=5.4 → screening
  only 1.3–1.9×). Re-measure the exact-evaluation reduction and, for the first time, net wall-clock.
- **T5 — Latent control (future).** Rollout / policy-improvement over the latent action coordinates
  `vℓ(a)` (Bertsekas rollout), i.e. a *spectrum-guided* policy, not a black-box GNN. Keep exact
  certification of the tie cluster so optimality is preserved.

## 6. Hypotheses (each falsifiable with our metrics)

1. **Multilinear response.** `R[n,a,r,m]` is low CP/Tucker rank (few modes capture most energy). —
   test: per-mode energy; compare to per-slice SVD.
2. **Gradient-weighting is necessary.** Score must weight modes by `u_iᵀ∇S`; unsupervised norm fails. —
   already confirmed (0.17 vs 0.37 Containment@1; the low-energy/high-gradient direction).
3. **Shared factors transfer.** Factors fit on some instances screen unseen instances better than
   per-node fits. — test in T3 (the central new claim).
4. **Interpretable modes.** Latent modes align with named operational phenomena. — test in T2.
5. **Scope honesty.** Net speedup requires large |A| / expensive children (N-track), not single-track. —
   already evidenced; quantify in T4.

---

## 7. Positioning vs AlphaZero / RL (the message)

AlphaZero learns `s→(π,V)` with MCTS + nets but does not ask whether the policy/value **response over
state-action pairs is low-rank**, which modes dominate decision quality, or which discarded directions
matter because the value gradient points along them. In structured optimization (B&P railway
scheduling, network design) the response is *not* arbitrary — it is generated by resource constraints,
trajectory incidence, dual prices, and bound updates, which form a tensor. Exploiting that tensor
yields policies that are **interpretable, transferable, and certifiable** — AlphaZero learns a policy;
this learns the *structure behind* the policy.

## 8b. Empirical results so far (sizes 8 & 10, `spectral_ttbl/tensor_response.py`)

Ran T1–T3 on single-track sizes 8 and 10 (8 train seeds → 5 unseen test seeds).

**T2 — the response tensor is genuinely low multilinear-rank (hypothesis 1 ✓).**
`R[action, section, metric]` HOSVD multilinear rank:

| size | tensor shape | multilinear rank @90% | note |
|---|---|---|---|
| 8 | 18 × 8 × 3 | **3 × 3 × 1** | metric mode rank-1 |
| 10 | 31 × 8 × 3 | **5 × 5 × 1** | metric mode rank-1 |

The **metric mode is rank-1** at both sizes — the per-section responses (occupancy, contention, …) are
one tightly-coupled signal. The dominant *energy* action-mode tracks the screening target inconsistently
(Spearman +0.34 at size 8, −0.07 at size 10) → **gradient weighting still needed** (hypothesis 2 ✓):
the top-variance mode is not reliably the score-relevant mode.

**T3 — supervised screening TRANSFERS across unseen instances (hypothesis 3 ✓), and a very low-rank
factor model matches the full model (parsimony).** Out-of-instance Containment / RankGap / Spearman:

| size | method | Contain@1 | Contain@5 | Spearman (unseen) |
|---|---|---|---|---|
| 10 | random | 0.23 | 0.70 | 0.02 |
| 10 | pseudo-cost | 0.32 | 0.74 | 0.02 |
| 10 | ridge | 0.38 | 0.79 | 0.38 |
| 10 | GBR | 0.41 | 0.79 | 0.39 |
| 10 | **rrr (rank-3 tensor)** | 0.39 | 0.79 | **0.40** |
| 8 | **rrr (rank-1 tensor)** | 0.37 | 0.86 | **0.34** = ridge |

Supervised models generalize to *unseen* instances (Spearman ≈0.34–0.40, Contain@5 ≈0.8–0.9) and
crush random/pseudo-cost (≈0). A **rank-1 (size 8) / rank-3 (size 10) reduced-rank tensor regression
equals the full ridge/GBR** — the transferable screening signal lives in a tiny shared factor space
(parsimony + interpretability, the tensor payoff), though it does not *beat* the full model on accuracy.

**Honest reading.** Confirmed: multilinear low rank (metric mode rank-1), gradient-weighting necessity,
cross-instance transfer, and rank-1–3 sufficiency. Not yet shown: a *gain* over a full black-box model
(low-rank matches, doesn't beat) and any wall-clock/node win (single-track tie clusters are large,
|A| small). Those require N-track/route-choice (T4).

## 8c. Deep multi-layer mapping — workflow results (sizes 8 & 10, rich 5-layer features)

The shallow `H/B→SVD→label` was replaced by the rich mapping (`tensor_features.py`: node / action /
**dual-proxy** / trajectory feature layers + 7-metric response + per-section response tensor). Four
parallel analyses (`tensor-response-analysis` workflow). The deeper pipeline **refines and partly
overturns** the earlier thin tensor study:

**(1) Decomposition — structure yes, interpretable taxonomy NO.** The per-section response tensor is
low multilinear rank — metric mode **rank-1** (98.4%/97.4% energy), HOSVD rank (5,4,1)/(6,5,1) — but it
is essentially **one interior/mid-line wait-time field** (occupancy≈0, contention minor; loads on
*interior*, not terminal, sections). The hoped-for *terminal-congestion / meet-pass / contention-relief*
mode taxonomy is **not supported** (CP components are sign-flipped near-duplicates; |ρ| with dStrong/dual
≤ 0.18). *(Fixed a CP-ALS bug: it ran on un-centered R; now grand-mean-centered for fair relerr.)*

**(2) Rich-vs-shallow transfer — the central test, with a key twist.** Adding feature layers improves
out-of-instance screening, but the credit goes to the **trajectory** layer, not the dual layer:

| feature set | C@5 (n8 / n10) | Spearman (n8 / n10) |
|---|---|---|
| action-only | 0.31 / 0.35 | +0.09 / +0.11 |
| action + **dual** | 0.25 / 0.34 | **+0.54 / +0.52** |
| action + **traj** | **0.47 / 0.51** | +0.78 / +0.78 |
| all 23 | 0.44 / **0.63** | **+0.82 / +0.85** |
| pseudo-cost / random | 0.38/0.33 / 0.22/0.27 | ~0 |

**The dual/optimization-state layer massively raises *global* rank-correlation (Spearman +0.1→+0.5) but
does NOT improve *per-node* Containment@5 (it slightly hurts).** Global ordering ≠ local top-K decision.
The **trajectory layer (train delay/completion/conflict-count)** is the consistent winner on *both*
metrics; the full model is best overall.

**(3) Low-rank multi-output — parsimony yes, accuracy edge no.** The coupled 7-metric response is
low-rank (n10 needs rank **2** of 7, n8 rank 5; Spearman saturates by rank 1–2). But low-rank
multi-output regression does **not** beat a single-output GradientBoosting on dStrong (GBM Spearman
0.83/0.84 vs RRR 0.76/0.79; GBM C@5 0.61 vs 0.48 on n10). Coupling buys parsimony/interpretability, not
screening accuracy. *(Caveat: RRR linear vs GBM nonlinear — conflates coupling with nonlinearity.)*

**(4) Feature-layer importance — trajectory dominates, dual is ~noise.** Permutation importance:
**traj 44% (n8) → 60% (n10)** (dominance grows with size); node 41%→20%; action 13%→19%; **dual 1–2%
(near-irrelevant)**. Top features recur across sizes: `gap_proxy` (node), `delay_i`/`delay_j` (traj),
`arr_gap` (action). Test R² ≈ 0.64–0.66.

### Refined conclusions (what the deep mapping actually shows)
- **Structure is real but simpler than hoped:** one low-rank wait-time response field, not a rich mode
  taxonomy. The "interpretable latent modes" pitch must be tempered.
- **The mapping matters — but it's the trajectory (train-delay) layer that carries the screening
  decision, not the dual layer.** The dual layer's value is *global rank-correlation*, which is the
  wrong target for per-node top-K branching. This global-vs-local distinction is a genuine methodological
  finding to report.
- **Low-rank tensor regression = parsimony, not accuracy.** A plain nonlinear single-target model is at
  least as good for screening; the tensor framing earns interpretability/transfer, not a leaderboard win.
- **Transfer works:** out-of-instance Containment@5 ≈ 0.5–0.63, Spearman ≈ 0.8, far above baselines —
  the screen genuinely generalizes to unseen instances.
- The dual-layer story likely needs *true LP duals* (LP-based N-track B&P), not the single-track
  contention proxies — a concrete reason the next experiment must be N-track/route-choice.

## 9. Honest caveats carried from Stages A–C
- Single-track has small candidate sets (mean |A|=5.4) and an already-strong earliest-conflict rule →
  no node-count speedup, screening only 1.3–1.9×. The tensor framework's payoff (transfer +
  interpretability + larger-|A| screening) must be demonstrated on **N-track / route-choice**, not
  single-track.
- The score gaps between meet-pass moves are small → large tie clusters; the contribution is
  *contain-the-tie-cluster-and-certify*, not pick-the-single-best.
- Keep the discipline: the tensor/learned layer changes only *which* candidates are inspected; exact
  child certification preserves validity and optimality.
